# 2026-10-15 工作日志

## 诊断：PUT /api/documents/1 返回 400 Bad Request

- **现象**：用 PowerShell 里的 `curl.exe -d '{"title":"...","fileType":"PDF"}'` 调 PUT 接口，返回 Spring 默认格式的 400（不是 controller 里自定义的 `{"error":"title and fileType must not be blank"}`）。
- **根因（已用回声服务器实测确认）**：PowerShell 把单引号字符串传给原生 exe（curl.exe）时，会**吞掉 JSON 里的双引号**。服务器实际收到的是 `{title:更新后的 Java 学习笔记,fileType:PDF}`，这不是合法 JSON，Jackson 反序列化 `@RequestBody Document` 失败 → 抛 `HttpMessageNotReadableException` → Spring 默认转成 400。controller 方法体根本没执行，所以看不到自定义错误。
- **结论**：Java 代码（Controller / Document / Mapper）没有问题，问题出在"PowerShell + curl.exe 的引号处理"。GET 不需要 body 所以正常；POST 之前能成功大概率是用 .http 文件（VS Code REST Client）发的，那个工具发的是合法 JSON。
- **修复方向**：发请求时避开 PowerShell 引号陷阱——优先用 .http 文件 / `Invoke-RestMethod` / `curl.exe -d "@file.json"`（文件用无 BOM UTF-8 写）。Java 侧可加 `@RestControllerAdvice` 捕获 `HttpMessageNotReadableException` 以便未来把这类 400 变得可诊断。
